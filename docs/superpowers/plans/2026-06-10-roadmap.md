# Roadmap การพัฒนา — ระบบสั่งอาหารล่วงหน้า กะเพราไฟลุก by MEAL TEAory

Spec อ้างอิง: `docs/superpowers/specs/2026-06-10-dorm-order-system-design.md`

ระบบแบ่งเป็น 5 เฟส แต่ละเฟสมี implementation plan ของตัวเอง และจบเฟสแล้วต้องได้ของที่รัน/ทดสอบได้จริง

| เฟส | ขอบเขต | Plan file | สถานะ |
|---|---|---|---|
| 1 | **Backend Foundation** — Supabase schema + RLS + seed เมนู + Edge Functions (create-order, verify-slip, update-order-status, line-webhook) + PromptPay QR + ตรวจสลิป + แจ้งเตือน LINE + expiry cron | `2026-06-10-phase1-backend.md` | แผนเสร็จ |
| 2 | **LIFF Customer App** — หน้าเมนู/ตะกร้า/เลือกเวลารับ → QR จ่ายเงิน → อัปสลิป → หน้าติดตามสถานะ | (เขียนเมื่อจบเฟส 1) | รอ |
| 3 | **Shop Dashboard (เว็บ)** — คิวออเดอร์ realtime + เสียงเตือน, ปุ่มเปลี่ยนสถานะ, ของหมด/ปิดรับ, จัดการเมนู, คิวคืนเงิน, สรุปยอดรายวัน | (เขียนเมื่อจบเฟส 2) | รอ |
| 4 | **Shop App + ปริ้นครัว** — ห่อ dashboard ด้วย Capacitor, ปริ้น ESC/POS ผ่าน TCP 9100 (เรนเดอร์ใบออเดอร์เป็นรูป), ปริ้นซ้ำ, สถานะปริ้นไม่สำเร็จ | (เขียนเมื่อจบเฟส 3) | รอ |
| 5 | **Integration & Launch** — ตั้งค่า LINE OA จริง (Rich Menu, LIFF id, group), EasySlip จริง, deploy production, ทดสอบ end-to-end ตาม Verification ใน spec | (เขียนเมื่อจบเฟส 4) | รอ |

เหตุผลที่เรียงแบบนี้: ทุกเฟสพึ่ง schema/edge functions ของเฟส 1; LIFF (เฟส 2) ทำก่อน dashboard เพราะสร้างออเดอร์จริงให้ dashboard ใช้ทดสอบ; ระบบปริ้น (เฟส 4) ต่อยอดจาก dashboard ที่เสร็จแล้ว

หมายเหตุ deviation จาก spec: ฟังก์ชัน `notify` ใน spec ทำเป็น **shared module** (`_shared/line.ts` + `_shared/messages.ts`) ที่ create-order/verify-slip/update-order-status เรียกใช้ตรงๆ แทนการเป็น edge function แยก — ลด hop และไม่ต้องทำ auth ระหว่าง function กันเอง
