# ระบบสั่งอาหารล่วงหน้า — ร้านกะเพราไฟลุก by MEAL TEAory (หลัง มช ซอย 7)

## Context (ที่มาและเป้าหมาย)

ร้านกะเพราไฟลุกต้องการให้ลูกค้าหอพักใกล้ร้าน **สั่งอาหาร → จ่ายเงิน → เดินมารับที่ร้าน** โดยไม่ต้องมายืนรอสั่งหน้าร้าน ลดคิวช่วงพีค ร้านใช้ Wongnai POS (Android) อยู่แล้ว แต่ Wongnai POS **ไม่มี API สาธารณะ** ให้ยิงออเดอร์เข้าอัตโนมัติ ระบบนี้จึงเป็น "ช่องทางออเดอร์แยก" เหมือนแท็บเล็ต Grab/LINE MAN แล้วให้ร้านกระทบยอดเข้า POS เอง

### ข้อสรุปจากการสอบถาม
- **ช่องทางลูกค้า:** LINE OA + LIFF (สั่งผ่านหน้าเว็บใน LINE ไม่ต้องโหลดแอป)
- **การจ่ายเงิน:** PromptPay QR + อัปโหลดสลิป + ตรวจสลิปอัตโนมัติผ่าน API (เช่น EasySlip/SlipOK)
- **ฝั่งร้าน:** ไม่ซื้อจอเพิ่ม — ใช้**มือถือ Android เก่า**ของร้านเป็นทั้งหน้าจอออเดอร์และตัวปริ้นออเดอร์อัตโนมัติเข้าเครื่องปริ้นครัว (เครื่องเดิมที่ต่อ LAN/WiFi ใช้ร่วมกับ Wongnai POS ได้ ไม่ชนกัน) + แจ้งเตือนเข้า LINE กลุ่มร้านเป็น backup
- **เมนู:** ตามสั่ง มีตัวเลือกเยอะ (เนื้อสัตว์ / ระดับเผ็ด / ไข่ / พิเศษ / หมายเหตุ)
- **เวลารับ:** รองรับทั้ง "รับเลย (ASAP)" และ "เลือกเวลารับล่วงหน้า"
- **คืนเงิน:** ร้านโอนคืนเองผ่านแอปธนาคาร แล้วกดยืนยันในระบบ
- **ปริมาณ:** ~ไม่เกิน 30 ออเดอร์/วัน
- **สถาปัตยกรรม:** LIFF + Supabase

## สถาปัตยกรรมรวม

```
ลูกค้า (LINE) ──LIFF app─────────┐
                                 ├──> Supabase (Postgres + Auth + Storage + Realtime + Edge Functions)
ร้าน (มือถือ Android เก่า)        │         │
  └─ Shop App (dashboard+ปริ้น) ──┘         ├──> EasySlip API (ตรวจสลิป)
       └─ ESC/POS ──> เครื่องปริ้นครัว       └──> LINE Messaging API (แจ้งลูกค้า + แจ้งกลุ่มร้าน)
          (LAN/WiFi เครื่องเดียวกับ Wongnai POS)
```

- **Frontend เดียว (React + Vite + Tailwind)** สองส่วน:
  - `/` — LIFF app ฝั่งลูกค้า (เปิดจาก Rich Menu ของ LINE OA)
  - `/shop` — หน้าจอร้าน (login ด้วย Supabase Auth, ใช้ Realtime + เสียงเตือนเมื่อมีออเดอร์ใหม่)
- **Shop App (Android, ห่อด้วย Capacitor):** เอาหน้า `/shop` เดิมห่อเป็นแอป Android ติดตั้งบนมือถือเก่าของร้าน เสียบชาร์จตั้งไว้ — เพิ่มความสามารถที่เว็บทำไม่ได้คือ **ปริ้นออเดอร์อัตโนมัติ** ผ่าน TCP (ESC/POS พอร์ต 9100) เข้าเครื่องปริ้นครัวทันทีที่ออเดอร์จ่ายเงินสำเร็จ
  - ใบออเดอร์เรนเดอร์เป็นรูปภาพ (raster) ก่อนส่งปริ้น เพื่อเลี่ยงปัญหา codepage ภาษาไทยของเครื่องปริ้นเทอร์มอล
  - เครื่องปริ้น LAN รับงานจากหลายแหล่งได้ — ไม่กระทบการปริ้นของ Wongnai POS
  - หน้า `/shop` ยังเปิดจากเบราว์เซอร์เครื่องอื่นได้เสมอ (มือถือเจ้าของ ฯลฯ) เพียงแต่ไม่มีปริ้นอัตโนมัติ
- **Supabase Edge Functions:**
  - `create-order` — รับออเดอร์, ล็อกราคาฝั่ง server, สร้าง PromptPay QR (dynamic ระบุยอด)
  - `verify-slip` — รับรูปสลิป → เรียก EasySlip → เช็คยอด/บัญชีผู้รับ/สลิปซ้ำ (transRef unique) → เปลี่ยนสถานะเป็น PAID → แจ้งร้าน
  - `notify` — ส่ง LINE push หาลูกค้า + ข้อความเข้ากลุ่มร้าน
  - `line-webhook` — รับ event จาก LINE OA (follow ฯลฯ)
- **ยืนยันตัวตนลูกค้า:** LIFF ID token → verify ฝั่ง server → ผูกกับ `line_user_id` (ไม่ต้องสมัครสมาชิก)

## Order Flow และสถานะ

```
PENDING_PAYMENT ─(สลิปผ่าน)→ PAID ─(ร้านกดรับ)→ COOKING ─→ READY ─(ลูกค้ามารับ)→ COMPLETED
   │ หมดเวลาจ่าย 15 นาที → EXPIRED
   └ (ร้านกดปฏิเสธหลังจ่าย เช่น ของหมด) → REFUND_PENDING ─(ร้านโอนคืน+กดยืนยัน)→ REFUNDED
```

1. ลูกค้าเปิด LIFF → เลือกเมนู+ตัวเลือก → ตะกร้า → เลือก "รับเลย" หรือเลือกเวลารับ → ยืนยันสั่ง
2. แสดง QR PromptPay พร้อมยอด → โอน → อัปโหลดสลิปใน LIFF
3. ระบบตรวจสลิปอัตโนมัติ → ผ่านแล้ว **ปริ้นใบออเดอร์เข้าครัวอัตโนมัติ** + หน้าจอร้านเด้ง+เสียง + ข้อความเข้า LINE กลุ่มร้าน
4. ร้านกด **รับออเดอร์** → ลูกค้าได้ LINE push "ร้านรับแล้ว ประมาณ X นาที" / กด **ปฏิเสธ** → เข้าคิวคืนเงิน
5. ร้านกด **เสร็จแล้ว** → push "อาหารเสร็จแล้ว มารับที่ร้านได้เลย (ออเดอร์ #12)"
6. ลูกค้าโชว์เลขออเดอร์ที่ร้าน → ร้านกด **รับของแล้ว**

ประหยัดโควต้าข้อความ LINE: สถานะทั้งหมดดูได้ในหน้า LIFF (สั่งแล้วเปิดดูได้ตลอด) ค่า default ส่ง push เฉพาะจุดสำคัญ (รับออเดอร์ / อาหารเสร็จ / แจ้งคืนเงิน ≈ 2-3 ข้อความ/ออเดอร์)

## Data Model (Postgres)

- `menu_categories` — หมวด (กะเพรา, ของทอด, เครื่องดื่ม)
- `menu_items` — ชื่อ, ราคาเริ่มต้น, รูป, `is_available` (ปุ่มของหมด)
- `option_groups` / `option_items` — กลุ่มตัวเลือก (เนื้อสัตว์ บังคับเลือก 1 มีราคาบวกเพิ่ม, ระดับเผ็ด, ไข่, พิเศษ) + ตาราง junction ผูกกับเมนู
- `customers` — `line_user_id`, ชื่อจาก LINE, เบอร์โทร (ขอครั้งแรก เผื่อร้านโทรตาม)
- `orders` — เลขออเดอร์รายวัน (#1, #2,…), ประเภท/เวลารับ, สถานะ, ยอดรวม, ข้อมูลสลิป (transRef, รูป), เวลาแต่ละสถานะ
- `order_items` — รายการ + snapshot ตัวเลือกและราคา ณ เวลาสั่ง (JSON) + หมายเหตุ
- `shop_settings` — เวลาเปิด-ปิด, ปุ่ม "ปิดรับออเดอร์ชั่วคราว", เวลาทำโดยประมาณ, PromptPay ID, LINE group ID

RLS: ลูกค้าเห็นเฉพาะออเดอร์ตัวเอง / ร้าน (role staff) เห็นทั้งหมด / เมนูอ่านได้สาธารณะ

## หน้าจอร้าน (Shop App บนมือถือ Android เก่า)

- คิวออเดอร์แบ่งคอลัมน์ตามสถานะ: ใหม่ (จ่ายแล้ว) / กำลังทำ / รอรับ — มีเสียงเตือน + ป้ายเวลารับ (ASAP/จองเวลา)
- ปุ่ม รับ / ปฏิเสธ / เสร็จแล้ว / รับของแล้ว
- **ปริ้นออเดอร์อัตโนมัติ**เมื่อจ่ายเงินสำเร็จ (ตั้งค่า IP เครื่องปริ้นในหน้า settings) + ปุ่มปริ้นซ้ำรายออเดอร์
- ใบออเดอร์มี: เลขออเดอร์ตัวใหญ่, เวลารับ (ASAP/จองเวลา), รายการ+ตัวเลือก+หมายเหตุ, ชื่อลูกค้า — จัดรูปแบบให้ครัวอ่านง่าย
- สวิตช์ "ปิดรับออเดอร์ชั่วคราว" + ปุ่มของหมดรายเมนู
- จัดการเมนู (เพิ่ม/แก้/ราคา/รูป/ตัวเลือก)
- คิวคืนเงิน: รายการที่ต้องโอนคืน + กดยืนยันเมื่อโอนแล้ว (แนบสลิปคืนได้)
- สรุปยอดรายวัน — สำหรับกระทบยอด/คีย์เข้า Wongnai POS ตอนสิ้นวัน

## Edge Cases

- **สลิปไม่ผ่าน** (ยอดไม่ตรง/บัญชีผู้รับผิด/สลิปซ้ำ): แจ้งลูกค้าใน LIFF ให้อัปใหม่หรือติดต่อร้าน — ออเดอร์ยังค้างที่ PENDING_PAYMENT จนหมดเวลา
- **ไม่จ่ายใน 15 นาที:** EXPIRED อัตโนมัติ (pg_cron)
- **นอกเวลาทำการ/ร้านปิดรับ:** LIFF แสดงปิดรับ สั่งไม่ได้
- **ของหมดหลังจ่าย:** MVP ปฏิเสธทั้งออเดอร์ → คืนเงินเต็ม (แก้บางรายการไว้เฟสหลัง)
- **EasySlip ล่ม:** ออเดอร์ค้างสถานะ "รอตรวจสลิป" → ร้านกดยืนยันสลิปด้วยตาเองได้ (manual override)
- **ปริ้นไม่ออก** (เครื่องปริ้นปิด/มือถือหลุด WiFi): ออเดอร์ยังเห็นบนหน้าจอ+LINE กลุ่มเสมอ แอปแสดงสถานะ "ปริ้นไม่สำเร็จ" พร้อมปุ่มปริ้นซ้ำ — การปริ้นเป็นส่วนเสริม ไม่ใช่จุดตายของระบบ

## ค่าใช้จ่ายโดยประมาณ (30 ออเดอร์/วัน)

| รายการ | ค่าใช้จ่าย |
|---|---|
| Supabase + hosting frontend (Vercel/Netlify) | ฟรี (free tier พอ) |
| ตรวจสลิป (EasySlip) | หลักร้อยบาท/เดือน (~900 สลิป/เดือน) |
| LINE OA push (~2-3 ข้อความ/ออเดอร์ ≈ 1,800-2,700/เดือน) | เกินโควต้าฟรี 300 ข้อความ → ต้องแพ็กเกจ Basic ~1,200฿/เดือน หรือปรับเหลือ 1 push/ออเดอร์ ("อาหารเสร็จ") เพื่อลดค่าใช้จ่าย |

*ตัวเลขแพ็กเกจจริงให้ตรวจสอบ ณ วันทำ — กำหนดให้จำนวน push ต่อออเดอร์ปรับได้ใน `shop_settings`*

## สิ่งที่ตัดออกจาก MVP (ไว้เฟสหลัง)

แต้มสะสม/โปรโมชั่น, คืนเงินบางรายการ, รายงานวิเคราะห์ยอดขาย, integration ตรงกับ Wongnai POS (ไม่มี API), ระบบคิวครัวขั้นสูง

## สิ่งที่ต้องเตรียม (ฝั่งเจ้าของร้าน)

1. LINE Official Account ของร้าน + เปิดใช้ Messaging API + สร้าง LIFF app
2. สมัคร EasySlip (หรือ SlipOK) + PromptPay ของร้าน
3. บัญชี Supabase (มีอยู่แล้ว — MCP เชื่อมต่ออยู่)
4. LINE กลุ่มพนักงาน + ดึงบอทเข้ากลุ่ม (สำหรับแจ้งเตือน backup)
5. มือถือ Android เก่า 1 เครื่อง เสียบชาร์จ + ต่อ WiFi วงเดียวกับเครื่องปริ้นครัว + หา IP ของเครื่องปริ้น (ดูจากใบ self-test หรือหน้า config เครื่องปริ้น)

## Verification (ทดสอบ end-to-end)

1. สั่งอาหารผ่าน LIFF (มือถือจริง) → จ่าย → สลิปจริงยอดไม่ตรง = ต้องไม่ผ่าน, ยอดตรง = PAID
2. หน้าจอร้านเด้ง realtime + มีเสียง + ข้อความเข้ากลุ่ม LINE + ใบออเดอร์ปริ้นออกที่เครื่องปริ้นครัว (ทดสอบภาษาไทย/ตัวเลือก/หมายเหตุบนกระดาษจริง)
3. กดรับ/เสร็จ → ลูกค้าได้ push ตามจุดที่กำหนด
4. ทดสอบ reject → คิวคืนเงิน → ยืนยันคืน → ลูกค้าได้แจ้งเตือน
5. ทดสอบ expire, ของหมด, ปิดรับออเดอร์, สลิปซ้ำ (อัปสลิปเดิมซ้ำ 2 ออเดอร์)
